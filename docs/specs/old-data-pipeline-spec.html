1. 背景與目標

建立一個台股篩選系統。資料來源為 FinMind（台灣開放金融資料平台，92 種台股資料集）。

核心決策：資料全部落地本地，篩選邏輯跑本地。不查詢時直接打 API。
理由：篩選要快、要能回測、要能離線改條件、篩選過程不能燒 API 額度。
⚠️ 已被推翻：「篩選系統」定位已於 2026-10-05 改為研究輔助系統（非全自動篩選器，不產出投資建議）。

2. 連接方式決策

FinMind 官方提供三種「串接方式」，本專案不採用任何一種作為資料來源。

方式實際是什麼本專案的定位
Agent Skill（/finmind 指令檔）一個 Markdown 指令檔，在 CLI 裡一句一句問開發期驗證欄位用
MCP Server（uvx finmind-mcp）AI 自動呼叫、適合多輪追問的 agentic 分析開發期資料探勘用
REST API / Python SDKapi.finmindtrade.com/api/v4 + FinMind.data.DataLoader唯一資料來源
理由：Agent Skill 與 MCP Server 都是給 AI 對話工具用的。它們沒有批次排程、沒有本地快取、每次對話重打 API、額度消耗最快。篩選系統需要的是可批次、可增量、可重跑的取資料管道。

3. 資料方案與額度

先不用付費，用免費 token 驗證整條流程。

3.1 額度與方案

方案價格限制資料集授權
FreeNT$0600 次/小時（一天 14,400 次）45Non-commercial
BackerNT$699/月1,600 次/小時81Non-commercial
SponsorNT$999/月6,000 次/小時97Non-commercial

關鍵限制：免費方案不能省略 data_id，只能逐檔抓。
授權範圍：使用者不得將即時資料直接呈現於 web、App 等對外介面，亦不得對外再散布原始資料或建立鏡像服務。本專案自用，符合。

3.2 免費方案的缺口

缺口影響處理方式
TaiwanStockPriceAdj（還原價）拿不到暫用未還原日線，UI 必須明確標示長區間報酬率會失真

✅ 已解決：還原價缺口已找到免費官方解法 —— TaiwanStockDividendResult 提供官方 reference_price 與 before_price， 因子 = reference_price / before_price，免 token（測試 16–19，10 檔 151 筆驗證通過）。

4. Token 機制（7 天期限）

免費 token 有效期 7 天（使用者實際觀察，官方文件未載明此期限）。

4.1 Token 有兩個消費者

消費者需要 token 的時機
Streamlit 介面使用者開著瀏覽器時
下載器 / 排程同步掛機 1.6 天、或每日 18:30 自動跑，使用者不在瀏覽器裡
結論：token 必須落地到檔案。只存 session state 會讓排程同步完全不可用。

4.2 落地方式

明文 .env + .gitignore（已確認採此方案）。

4.3 額度與有效性查詢

# 原文寫法
GET https://api.web.finmindtrade.com/v2/user_info
Authorization: Bearer {token}
→ { user_count, api_request_limit }
⚠️ 已被推翻（實測 2026-10-06）：
端點HTTP回應
api.finmindtrade.com/api/v4/user_info404不存在
api.web.finmindtrade.com/v2/user_info200{"msg":"請輸入 token","status":400}
→ 無 token 無法查詢額度。

4.4 過期防護三層

  1. 記錄 token_saved_at，UI 顯示倒數
  2. 每次同步開始前先打 /user_info 做 pre-flight 檢查
  3. 抓取中每 100 requests 再驗一次
⚠️ 已被推翻：第 2、3 層依賴 /user_info，該端點無 token 時不可用 → 「同步前檢查 token」的保護機制不可靠，spec §4.3 的 pre-flight 步驟需改寫。

5. FinMind 安全協議與合規做法

5.1 官方協議內容

  • 傳輸層：所有端點皆為 HTTPS/TLS
  • 認證層：Bearer token 置於 Authorization header
  • 儲存層：無規定。隱私權政策第 10 條僅要求「妥善保管存取憑證，避免外洩」

5.2 本專案的合規措施

措施防什麼
僅 HTTPS傳輸竊聽
Token 走 Authorization header，不放 query stringtoken 進伺服器 access log
.env 進 .gitignore真正的外洩管道：此為 git repo 且兩台電腦共用
.env 檔案 ACL 限制當前使用者同機器其他帳號讀取
Token 不寫入 Obsidian／handoff／commit message專案既有規則已涵蓋
Log 僅顯示 token 前 4 碼貼 log、截圖時外洩

6. IP 封鎖政策與請求策略

官方文件明載：短時間內累積大量 4xx 請求會觸發 IP 封鎖，封鎖 30 分鐘。

6.1 分級重試策略

回應處理
4xx（TokenIllegal 等）不重試，立即停止該 dataset
402（額度用完）非錯誤，停止並記錄
5xxexponential backoff，最多 3 次
403 + ip banned全域停止，標記「封鎖中，30 分鐘後解除」

6.2 請求速率

單執行緒，每 7.2 秒一次請求（500 次/小時，額度 600 留 100 緩衝）。不使用併發。
官方壓力測試顯示伺服器可承受 10～50 requests/秒，但本專案的瓶頸是帳號額度 600/小時（0.167 requests/秒），非伺服器能力。
設計修正紀錄：先前建議「併發 5～10」是錯的，已收回。

6.3 維護時段

每週日凌晨 00:00～03:00 伺服器維護。1.6 天掛機下載必然經過此時段，同步器需自動暫停並於 03:00 後續跑。

7. 資料集分級

不採「全部下載」策略。92 個資料集中有多張高頻巨獸。

7.1 陷阱：5 秒頻率資料集

資料集頻率全市場估算量
TaiwanStockStatisticsOfOrderBookAndTrade每股每 5 秒1,900 檔 × 3,240 筆/日 ≈ 615 萬筆/日，一年 1.5 億列
TaiwanVariousIndicators5Seconds每 5 秒91 檔指數

7.2 核心層（優先抓，免費可取得）

TaiwanStockPrice                    TaiwanStockFinancialStatements
TaiwanStockPER                      TaiwanStockBalanceSheet
TaiwanStockMonthRevenue             TaiwanStockCashFlowsStatement
TaiwanStockInstitutionalInvestorsBuySell
TaiwanStockMarginPurchaseShortSale

TaiwanStockDividend                 TaiwanStockDividendResult

成本：12 個 × 1,900 檔 ≈ 22,800 requests ≈ 免費方案 1.6 天。

7.3 中繼層（各 1 次 request）

TaiwanStockInfo、TaiwanStockTradingDate、TaiwanStockTotalReturnIndex、TaiwanStockNews 等。

7.4 排除層

5 秒頻率表、可轉債全系列（backer 起）、即時快照（sponsor）、TaiwanOptionVix（backer 起）。

8. 已知資料陷阱

FinMind 官方文件明載四點，全部寫進 transform/ 層，不在 raw_ 層處理。
  1. 興櫃個股 open 是「前日均價」不是開盤價 — 可能落在當日 max/min 之外。不要用 open 計算任何指標。
  2. 當日無公告成交價時 OHLC 全為 0，但 Trading_Volume 可能是 451。用 close > 0 判斷，不要用 Trading_Volume > 0。
  3. TaiwanStockInfo 一檔股票可能有多列 — 取同一 stock_id 中 date 最新的那一列。
  4. 還原價基準 — 以最新交易日為基準往前累乘。
⚠️ 遺漏：本節未納入實測發現的靜默錯誤陷阱 — origin_name 中文名重複（NetIncome vs IncomeAfterTaxes、 CapitalStock vs CapitalStock_per）、 以及 TaiwanStockInfo 實為變更事件流（4,329 列／300+ 個 date／32 列 date=null）的完整處理規則。

9. 系統架構

FinMind REST API / SDK
      │
      ▼
core/finmind_client.py   HTTPS + Bearer header + token bucket + 分級重試
core/quota.py            /user_info 額度與有效性
core/datasets.py         資料集註冊表
core/token_store.py      token 讀寫 + saved_at
      │
      ▼
storage/writer.py        Parquet 分區寫入（raw 層，不可變）
storage/sync_state.py    水位線表
      │
      ▼
DuckDB (read_only)       查詢層
      │
      ▼
transform/               型別正規化、興櫃與無價日修正
      │
      ▼
metrics/                 衍生指標：報酬率、均線、波動、PER/PBR
      │
      ▼
screener/                篩選條件 = 純函式 (DataFrame → DataFrame + 命中理由)
      │
      ▼
app/ (Streamlit)         網頁介面

9.1 raw 層用 Parquet，不用 DuckDB 寫入

原因：DuckDB 單寫者限制。下載器掛機或排程同步時會與同時開啟的 Streamlit 搶檔案鎖。Parquet 為檔案級追加，兩者不衝突。

9.2 raw 層不可變

raw_<dataset> 只追加、不 UPDATE、不轉型。所有修正在 transform/ 層。

9.3 抓取冪等

dataset | stock_id | last_date | last_sync | row_count | status
  • 每次同步只抓 date > last_date 的部分
  • 每完成一個 stock_id 即 commit，中斷後 --resume 從水位線繼續
  • 失敗的 stock_id 記錄待重試，不讓單筆失敗拖垮整批

9.4 screener 是純函式

輸入 DataFrame、輸出篩選結果與命中理由，不碰 IO。篩選邏輯可單獨測試，改條件不需重啟服務。

9.5 交易日與排程

排程時間 18:30 之後執行，避開未 complete 的資料與週日 00:00～03:00 維護時段。

10. 一鍵啟動

技術棧：Python + DuckDB + Streamlit。依賴管理用 uv。

:: start.bat
uv sync
uv run streamlit run app\main.py
資料抓取不綁在啟動流程裡。啟動只開介面；資料不足時 UI 顯示「資料截至 X 日」並提供同步按鈕。
