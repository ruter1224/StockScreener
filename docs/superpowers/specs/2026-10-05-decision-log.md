## 1. 資料層查證結果

### 1.1 FinMind `TaiwanStockInfo` 的真實結構 ✅

端點：`https://api.finmindtrade.com/api/v4/data?dataset=TaiwanStockInfo`

```
總列數              4,329
distinct stock_id   3,151
distinct 產業值        57
列數 by type        twse 2402 / tpex 1376 / emerging 551
```

**這不是主檔，是變更事件流。** 同一支股票在不同 `date` 各有一列，全庫橫跨 300 多個不同 `date`：

```
2026-10-05   rows=3317    ← 最近一次完整快照
None         rows=32      ← 31 檔創新板 + 1 檔，date 為 null
其餘 300+ 個 date，每個 1～179 列不等
```

後果：

1. **必須 upsert，不可 append。** 同一 `stock_id` 會重覆寫入。
2. **`date = null` 的列排序行為不可依賴。** 各資料庫對 null 的排序方向不同，這 31 列若參與「取最新」運算，可能覆蓋掉有真實日期的正確資料。→ transform 層需明確規則：null date 一律視為「早於所有有日期的列」，且需記錄計數以便對帳。
3. canonical spec §8-3 已有「取同一 stock_id 中 date 最新那一列」的規則，但只描述了「興櫃轉上市保留兩列」的情況，**未涵蓋事件流結構**。需擴充。

### 1.5 創新板實態 ✅

**查證前的主要誤解：創新板股票並不存在於官方資料之外。**

```
曾被 FinMind 標記為創新板的 distinct stock_id：37
  其中 type = twse：37 / 37
  有官方產業代號：  37 / 37
  官方代碼分布：
     22 生技醫療  8   35 綠能環保   8   24 電子零組件  6
     36 數位雲端  6   12 半導體     4   05 食品       1
     15 電機機械  1   29 電子工業   1   28 電子工業   1
     27 其他電子   1   31 其他電子   1   25 電腦週邊   1
```

→ **創新板公司就是上市公司，正常存在於 TWSE API 內，產業代碼完整。** 不需要新 API adapter，不需要獨立 board。

**FinMind 標籤本身有雜訊，三個具體問題：**

1. **同一個板有兩種字串寫法**，且是跨時間的：
   ```
   2024-12-04  創新版股票  n=18   ← 舊寫法（用「版」）
   2026-10-05  創新板股票  n=31   ← 現行寫法（用「板」）
   ```
   例：`2254 巨鎧精密-創`、`2432 倚天酷碁-創`、`3150 鈺寶-創` 在 2024 年標「創新版股票」，2026 年標「創新板股票」。
   → 只比對單一字串會漏檔。必須同時接受 `創新板` 與 `創新版`。

2. **有時間倒退的軌跡**：
   ```
   6869 雲豹能源-創   2023-03-17/創新板股票  →  2024-11-25/創新版股票
   6873 泓德能源-創   2023-03-17/創新板股票  →  2024-11-25/創新版股票
   ```
   寫法從「板」變回「版」，方向與第 1 點相反。代表 FinMind 的標籤值本身不一致，不是乾淨的狀態欄位。

3. **部分檔案標籤停滯**：`6757 台灣虎航-創`、`6869`、`6873` 的最新一列停留在 2024 年，未出現在 2026-10-05 快照中。可能已轉出創新板，也可能是 FinMind 未更新。**未查證。**

**檔數統計的正確數字：**

| 定義 | 檔數 |
|---|---|
| 曾被標記為創新板（全部歷史） | 37 |
| 2026-10-05 快照中標記為創新板股票 | 31 |
| 官方 API 有對應代號 | 37（100%） |

> 📌 修正紀錄：先前口頭回報「23 檔」是錯的，原因是驗證腳本在選取「最新日期」時 mishandle 了 32 列 `date=null` 的資料。正確為 37（歷史）/ 31（最新）。

### 1.6 興櫃實態 ✅

```
FinMind type = emerging 的 distinct stock_id：387
  有官方產業代號：  0
  無官方產業代號：387（100%）
```

**興櫃是未上市市場，TWSE / TPEx 的公司基本資料 API 天然不包含。** 這才是需要切割的對象。

FinMind 對興櫃股票仍提供**完整的產業名**：

```
生技醫療業 98   半導體業 35   綠能環保 29   光電業 23
電機機械   22   電子零組件業 21   其他 20   電腦週邊 17
資訊服務業 15   其他電子業 15   觀光餐旅 15   數位雲端 12
通信網路業 12   化學工業 10   文化創意業 9   食品工業 8
金融業 5   運動休閒 4   鋼鐵工業 3   居家生活 3   農業科技 3
航運業 2   電子通路業 2   建材營造 2   紡織纖維 1
```

→ 興櫃的產業分類**做得到**，直接沿用 FinMind `industry_category` 即可，不需要新 adapter。

⚠️ 但興櫃股票**無上市財報**（canonical spec §8-1、§8-2 已載明興櫃的 `open` 與無價日問題）。這才是納入興櫃的真正成本，不是產業分類。

### 1.7 FinMind `industry_category` 不可作為現行分類依據 ✅

1. **含非產業值**：57 個值中混有 board 標籤（`創新板股票`、`創新版股票`）與非個股類別（`ETF`、`ETN`、`指數`、`權證`、`受益證券`、`存託憑證`、`所有證券`、`大盤`）。
   > 修正紀錄：先前把 `創新板股票`、`創新版股票` 列為「非個股」是錯的，兩者是 board 標籤。

2. **分類版本落後**：`電子工業` 對應官方 W24–W31 共 8 個細類，是舊版上層分類。已抽查確認為合理上層分類而非亂碼（川湖/台達電 → W28、華碩/技嘉/廣達 → W25、億光 → W26）。但無法用它做當前細類同業比較。

3. **`其他` 共 194 列**，為未分類桶。

4. **同代號可能同日多列衝突**：`6438` 在 2026-10-05 有兩列，行業分別為 `其他電子業` 與 `電子工業`。

## 2. 已同意的決策

### 2.1 產業分類來源 ✅

以 **TWSE / TPEx 官方 API 為 source of truth**，FinMind `industry_category` 降級為歷史對照用途。

### 2.2 切割線與 board 策略 ✅

- **v1 啟用**：`twse`、`tpex`
- **v1 不啟用**：`emerging`（興櫃），但 schema 預留
- **創新板不切**：已在官方資料內，無需獨立 board

採「資料驅動開關」而非程式碼預留：

```yaml
# config/boards.yaml
boards:
  twse:
    enabled: true
    industry_source: TWSE_產業別
  tpex:
    enabled: true
    industry_source: TPEx_SecuritiesIndustryCode
  emerging:            # 興櫃：未上市，官方無資料，無財報
    enabled: false
    industry_source: FinMind_industry_category
    has_financials: false
```

理由：開關與 `has_financials` 是**資料**，不是預留程式碼。啟用興櫃時只改 YAML。

### 2.3 stock master 複合鍵 ✅

主鍵用 `(stock_id, board)`，保留轉上市／轉上櫃軌跡（`6438` 為已確認案例：tpex → twse）。

⚠️ **未決**：同一 board 內產業變更（例：某公司由 W24 改為 W35）是否需要 `valid_from` / 版本欄位。複合鍵無法表達這類變化。

### 2.4 產業代碼儲存格式 ✅

存乾淨代碼字串（如 `"28"`），不存 `W` / `T` 前綴。市場別由 `board` 欄位區分。

### 2.5 創新板標記 ✅

使用者決定：**創新板股票納入系統，且篩選輸出時必須標註**，因為其買賣規則與一般上市股不同。

⚠️ **未查證**：創新板的具體交易限制內容。spec 只寫 flag 機制，不寫法規細節。法規應放獨立文件並引用官方來源，避免法規變動時要改架構。

標記實作方式的風險評估：

| 來源 | 覆蓋 | 問題 |
|---|---|---|
| FinMind `industry_category` 含「創新」 | 37/37 | 值不一致（「板」/「版」）、時間倒退、部分停滯 |
| 股票簡稱結尾為「創」 | 37/37 | ⚠️ **有誤判風險**：正常上市公司如「群創」也以「創」結尾 |

→ **結論：兩者都不可單獨使用。** 主判準用 FinMind 的「創新板／創新版」標籤，簡稱後綴僅作交叉檢查並記錄異常，不作為獨立判準。

### 2.6 人工輸入的時間戳與備註 ✅

- 人工評分與未來 EPS 預估採 **append-only**，帶時間戳，不覆寫歷史
- 每筆可附**可選備註**，允許 `NULL`

### 2.7 衝突 1：兩套估值如何並存 ✅（2026-10-06 決定）

**決定：採方案 A —— 兩套獨立計算並存。**

| 項目 | 內容 |
|---|---|
| 安全邊際（模式 A）| 5 年願景：`長期價值 = 近12月EPS × (1+產業CAGR)^5 × 目標PER`，輸出單一安全邊際 % |
| 追價安全圈（模式 B）| 2 年實際：`地板價 = 預估2年後EPS × PER下限`、`天花板 = 預估2年後EPS × PER上限`，輸出三態（低於地板／區間內／超過天花板）|
| 關係 | 兩者**獨立計算、各自輸出**，不互相推導或設為對方的硬門檻 |
| 理由 | 兩者服務不同需求（價值投資 vs 追價保護）；現無真實資料判斷哪個較有鑑別力；不提前綁死，待 Phase 1 取分布後再評估是否調整 |

**安全邊際門檻處理**：
- **不設死硬門檻**，改為輸出原始安全邊際 %
- 提供**可設定門檻**，預設 **50%**
- 介面提示：「講義建議 >100%，但講義所有實測案例最高僅 93%，100% 門檻從未驗證」
- 待 Phase 1 取真實分布後，再決定是否調高門檻或讓安全邊際升級為硬門檻

### 2.8 衝突 2：ROE 門檻由使用者設定 ✅（2026-10-06 決定）

**決定：ROE 範圍由使用者在一開始設定，再帶入篩選系統。**

```
使用者設定 ROE 範圍 → 帶入篩選條件 → 作為量化層第一道篩選
```

**具體規則**：

| 項目 | 內容 |
|---|---|
| ROE 門檻 | **由使用者在一開始設定**（區間或門檻值），帶入篩選系統 |
| 甜蜜區提示 | 講義統計 10-15% 為甜蜜區；使用者設在此範圍外時提示「已離開講義統計甜蜜區」 |
| 實作方式 | 門檻存於設定檔（`config/thresholds.yaml`）與程式碼分離；Streamlit 設定頁提供輸入；篩選執行時讀取設定 |
| 理由 | 符合 D1「量化層 = 可配置篩選條件群」；門檻先於架構（D3），寫骨架前確定可避免日後重構 |

**其他三個門檻維持講義設定值**（2026-10-06 決定）：

| 門檻 | 值 | 來源 |
|---|---|---|
| 業外獲利比 | [0.8, 1.2] | 講義 |
| 財務槓桿 | < 3.0 | 講義 |
| align_score | < 8.0 | 講義 |

→ 這三個**先寫在設定檔作為預設值**，但欄位設計為可覆寫，避免日後要參數化時重構。

### 2.9 Tier → 目標 PER 對應表 ✅（2026-10-06 查證講義原文補入）

> 📌 本節原本在 `conflict-review.html:70` 被宣稱「已收進決策紀錄」，但實際全文查無此表。
> 2026-10-06 重新查證 NotebookLM「財經」筆記本後補入。

| 總分 | Tier 定義 | 目標 PER | 講義原文舉例 |
|---|---|---|---|
| 85~100 | Tier S 夢幻企業 | **35~40 倍** | 輝達（幾乎無缺點） |
| 70~84 | Tier A 頂級成長 | **25~30 倍** | 台積電、致茂、旺矽 |
| 55~69 | Tier B 穩健優質 | **15~20 倍** | 世芯-KY、緯穎、萬潤、奇鋐 |
| 40~54 | Tier C 一般企業 | **10~15 倍** | 廣達、鴻海 |
| < 40 | Tier D 價值陷阱 | **5~10 倍** | 景氣循環股 |

五大維度**各占 20 分**，每維再分四級：

| 分數區間 | 等級 |
|---|---|
| 20~16 | 頂級／極優 |
| 15~11 | 優秀／穩健 |
| 10~6 | 普通／及格 |
| 5~0 | 落後／危險 |

維度與評分用語（講義原文）：

| # | 維度 | 20~16 | 15~11 | 10~6 | 5~0 |
|---|---|---|---|---|---|
| 1 | 產業鏈地位 | 統治者 | 關鍵寡佔 | 供應鏈要角 | 價格接受者 |
| 2 | 產業成長性 | 爆發成長(>30%) | 高速成長(20~30%) | 溫和成長(10~20%) | 停滯或衰退(<10%) |
| 3 | 企業護城河 | 無法替代 | 高門檻 | 中等門檻 | 無護城河 |
| 4 | 財務商業模式 | 印鈔機模式 | 優質製造 | 辛苦錢(代工) | 體質脆弱 |
| 5 | 風險折扣因子 | 極低風險 | 可控風險 | 高風險 | 極度危險 |

⚠️ **風險折扣因子是階梯跳級，不是連續打折**。台積電原文：20+18+20+18+**6**（風險折扣，理由「致命的地緣政治」）= 84 分 → Tier A 25~30 倍。若該維度拿滿 20 分，總分 98 → Tier S 35~40 倍。
→ **單一維度 14 分差距，讓目標 PER 差將近 10 倍。** 與 §4.11 原先描述的「目標本益比要不要打折」有本質落差。

### 2.10 「站隊加權 30/30/25/15」的真正意義 ✅

**這不是 Tier 分數門檻，是產業站隊的四個維度權重。**

| 權重 | 維度 | 原文定義 |
|---|---|---|
| 30% | 政策護城河 | 產業是否被列為戰略重點、享有補貼或保護 |
| 30% | 地緣韌性 | 產線與供應鏈地理佈局是否分散且友岸化 |
| 25% | 定價權力 | 是否有能力把關稅與成本轉嫁給客戶 |
| 15% | 生產效率 | 自動化與在地化程度 |

判斷基準：加權總分 **≥8 核心配置／6~7 中性觀察／<5 排除**。

> 📌 修正紀錄：`conflict-review.html:70` 把這組數字與 Tier→PER 對應表並列，容易被誤讀為同一套門檻。兩者無關。

| 機制 | 評分 | 講義效果 | v1 決策 |
|---|---|---|---|
| 產業結構惡化否決過濾（模組一 指標 3）| 0~10 | **7~10 分直接剔除** | **不做，只記錄** |
| 企業體質惡化風險否決過濾（模組二 指標 4）| 0~10 | **7~10 分直接剔除** | **不做，只記錄** |

不做的理由：兩者都是 0~10 主觀評分，實際打分需「和同業比」，而 v1 連同業對照資料都還沒準備。先讓 ROE／業外比／槓桿三道跑起來，看到真實分布再決定是否加入。

### 2.12 產品契約與工作流程 ✅（2026-10-06 grill 決定）

**使用者輸入篩選條件 → 系統依條件初篩 → 使用者人工評分挑選。**

| 項目 | 決定 | 說明 |
|---|---|---|
| 產出契約 | **初篩清單**，非全自動評分 | 量化層只輸出通過／不通過＋命中理由（D1）|
| 人工評分是核心功能 | **不可砍** | 五維評分 → Tier → PER → 安全邊際／安全圈，全鏈路都要做 |
| 篩選誤殺 | **開「略過篩選」入口** | 輸入代號可跳過硬門檻直接評分，硬門檻不是絕對門 |

### 2.13 ROE 篩選算法 ✅（2026-10-06 grill 決定）

| 項目 | 決定 |
|---|---|
| 篩選用 ROE | **講義的多年平均**（3 年或 5 年年度 ROE 再平均） |
| 另保留 | **TTM ROE** 作為「當期獲利品質」參考顯示，不參與篩選 |
| 本益比 | **只做提示，不設門檻** |

**PE 提示做法**：計算「當前近一年平均 PE ÷ Tier 目標 PER」比值。
當前 PE 高於 Tier 目標區間時提示「目前本益比高於目標區間」。

理由（§4.5 交叉表）：講義全表最高報酬 13.8% 出現在「ROE 5~10% ＋ PE 5~10 倍」，
「ROE 15~20% ＋ PE 20~25 倍」僅 2.1%。只設 ROE 下限會放行報酬最差的「高 ROE＋高 PE」組合。
⚠️ 但**不設硬門檻**：與 Tier 目標 PER 概念層級不同（當前 vs 應該值），且會增加使用者維護負擔。

### 2.14 維度 2 產業 CAGR 對照表 ✅（2026-10-06 grill 決定）

**決定：維度 2 維持「未來 5 年產業 CAGR」定義，採手動輸入 CAGR ＋ 系統換算建議分數。**

講義分級標準（原文）：

| 產業 CAGR | 建議分數 |
|---|---|
| > 30% | 16~20（爆發成長）|
| 20~30% | 11~15（高速成長）|
| 10~20% | 6~10（溫和成長）|
| < 10% | 0~5（停滯或衰退）|

對照表設計（可編輯，存 CSV／YAML）：

| 欄位 | 說明 |
|---|---|
| 產業代碼 | 官方 TWSE／TPEx 代碼（§1.3）|
| CAGR | 未來 5~10 年預估值 |
| 來源機構 | IDC／TrendForce／Gartner 等 |
| 抓取日期 | CAGR 會隨機構與年份變動，必須記錄 |

⚠️ **講義未提供全市場對照表**，原文指定由使用者自建：
「無須買報告，只需要開頭的 CAGR 即可，也可以直接問 ChatGPT」。

⚠️ **命名空間錯配**：講義 17 項是**主題產業**（人工智慧、5G FWA），
官方代碼是另一套（§1.3 的 33+28 種），官方**沒有「人工智慧」這個產業代碼**。
「人工智慧 30%」要對應到哪個官方代碼沒有講義依據 → **初期覆蓋率必然低，多數股票落在「無資料」狀態**。

⚠️ **CAGR 不是固定值**：講義內部對同一產業給過不同數字（營光電 CCL 6%、散熱 8%、半導體製造 8% vs 半導體 7%）。依賴查哪家機構、哪一年。

### 2.15 追價安全圈的「2 年後 EPS」✅（2026-10-06 grill 決定）

**決定：全手動輸入，系統不做任何自動預測。**

講義原文列三種來源，第一優先是機構共識 EPS：
> 預估未來 2 年 EPS = 近 12 個月累計 EPS × (1 + 產業 CAGR)²
> 「當系統抓不到機構預估值時，系統會自動啟動備用算式」

**實測結果（2026-10-06）**：FinMind **沒有**任何共識 EPS／預估 EPS／目標價類的 dataset。
以已驗證可用的 `TaiwanStockPER` 為對照（同參數回 200），
`TaiwanStockConsensus`／`TaiwanStockEstimate`／`TaiwanStockTargetPrice` 全部回 422 enum 錯誤。

→ **機構共識 EPS 需 CMoney／FactSet／Bloomberg／券商 API，均為付費。**

**決定不採用講義的 CAGR 外推備援式**，理由：
1. 外推式與 §2.14 的維度 2 共用同一個不確定輸入，會產生假精確的假數字
2. 講義自己警告：「小型股可能會因時間而被產業淘汰，導致無法跟上產業複合成長率」
3. 講義明確警告：「一般 AI 概念股不能直接用【產業成長率】或【自身成長率】倍數去套」
4. §2.7 已定案兩套估值「各自輸出」，安全圈的輸入若由系統代填，會模糊「系統計算」與「人給的假設」的界線

→ 介面只提供輸入框，系統只負責算地板價／天花板。**關鍵假設由人負責，與「略過篩選」同一種設計邏輯。**

⚠️ **並列輸出時的誤讀風險**：長期價值用**歷史 EPS**（近 12 個月累計），
安全圈用**預測 EPS**（2 年後）。同一畫面並列時需明確標示，兩者不可當同一量尺讀（同 §2.7 的年化差異問題）。

### 2.16 長期價值公式的 CAGR 獨立設定 ✅（2026-10-06 grill 決定）

**決定：長期價值公式的 CAGR 與維度 2 的產業 CAGR 分開，不綁定。**

```
維度 2 的產業 CAGR  → 決定「賽道好不好」（評分）
長期價值公式的 CAGR → 假設「這家公司 5 年 EPS 成長多快」（估值）
```

⚠️ **若共用同一數字，維度 2 的影響會被計算兩次**：維度 2 高分 → 產業 CAGR 高 → 公式裡 EPS 成長假設也高 → 長期價值再被放大一次。

講義原文直接否定「公司成長率 = 產業 CAGR」這個假設：
> 「小型股可能會因時間而被產業淘汰，導致無法跟上產業複合成長率」

實作：長期價值公式的 CAGR 為**獨立可設定欄位**，預設可帶入維度 2 的值方便快速輸入，但使用者可改。

→ 本項同時關閉 §6 #15（原「長期價值假設公司 EPS 成長率 = 產業 CAGR 是否加修正」的待決）。

### 4.2 D1 讓架構簡化

原本爭論「量化要不要轉成 0-100 分與主觀加權平均」。D1 決定量化**不參與計分**：

```
量化層  = 可配置篩選條件群（ROE > 門檻、業外獲利比 ∈ [a,b]、財務槓桿 < N）
          → 輸出：通過 / 不通過 + 命中理由，不是分數
主觀層  = 五大維度 0-100 → 總分 → Tier → 目標本益比
```

沒有加權平均，兩層量尺各自獨立。

### 4.3 關鍵結構發現：量化指標就是維度 4 的輸入

講義的「五大維度」（主觀評分）與「五階層杜邦」（量化拆解）有直接對應：

| 五大維度 | 五階層杜邦 | 可自動程度 |
|---|---|---|
| 1. 產業鏈地位 | — | 全人工 |
| 2. 產業成長性 | — | 依賴外部 CAGR 資料 |
| 3. 企業護城河 | — | 全人工 |
| **4. 財務商業模式** | 稅賦優勢 / 業外獲利比 / 利益率 / 資產周轉率 / 財務槓桿 | **可自動預填** |
| 5. 風險因子 | 客戶集中度 / 財務槓桿 | 部分自動 |

→ 杜邦六項算完不是丟掉，是**拿來當維度 4 評分時的參考面板**。

> 📌 **修正紀錄（2026-10-06）**：本節原寫「杜邦六項算完拿去**預填**維度 4」，該說法錯誤。
> 查證講義原文後確認：
> - 五大維度是**五個相加的評分項，各占 20 分**，杜邦五項**不在任何一個維度內**
> - 杜邦是模組二「指標 2：五階層杜邦結構檢驗（獲利品質）」，屬**獨立的量化分析工具**
> - 維度 4「財務商業模式」在講義裡是**主觀歸類**（印鈝機模式／優質製造／辛苦錢(代工)／體質脆弱），
>   與杜邦的連乘分解是不同層次的東西，中間沒有講義依據定義映射規則
>
> **已決定**：維度 4 **維持人工評分**，杜邦五項僅作參考數據顯示，不自動決定維度 4 分數。
> ⚠️ 維度 4 名稱易誤導 —— 它不是財務指標，是「這家生意好不好做」的主觀判斷，
> 性質與維度 1（產業鏈地位）、維度 3（護城河）相同。**五大維度中僅維度 2 有客觀數字可對照（CAGR）。**

### 4.4 ROE 定義（已查講義原文）

講義原文：`賺錢效率(ROE)　稅後淨利 ÷ 股東權益`

| 項目 | 決議 | 依據 |
|---|---|---|
| 分子 | **稅後淨利**（含少數權益） | 講義原文；非歸屬母公司業主 |
| 期間 | **TTM（近四季）** | D9；與講義範例「過去 12 個月的累計 EPS」一致 |
| 分母 | **平均股東權益** | D7 |

⚠️ **與講義原文的差異**：原文只寫「股東權益」，未指定期初／期末／平均。採平均股東權益是刻意的工程決策，spec 需註明此為偏離原文的選擇。理由：增資或大額減資會使期末權益失真。

⚠️ 使用者 D7 稱「我的資料裡面是用那個（平均）做分母」，但查證講義原文並無「平均」二字。此為使用者理解與講義實際內容的落差，已如實記錄。

### 4.5 ROE 門檻：講義自帶「越高越差」統計

資料期間 2003-12-31～2024-12-31，分級方式為**過去 5 年平均 ROE**：

| 過去 5 年平均 ROE | 未來 5 年年化報酬 |
|---|---|
| < 5% | 6.1% |
| 5%~10% | 8.7% |
| **10%~15%** | **8.4%** |
| 15%~20% | 7.6% |
| 20%~25% | 6.7% |
| 25%~30% | 4.2% |
| > 30% | **2.9%** |

講義結論原文：「越高的 ROE 通常意謂越昂貴的價格；太低的 ROE 則表示企業競爭力不足，最理想的狀況是『好公司，也要買的便宜』」。

**含意**：門檻拉高等於自動排除高槓桿、小型股、景氣循環股。ROE 12% 落在甜蜜區合理；若日後想拉高到 20~25% 挑「優秀公司」，依講義自己的數據那是報酬最差的區間。

⚠️ 單一講者、單一期間的觀察，非因果。但這是本專案參考的原始資料，不得忽略。

#### ⚠️ ROE 必須用多年平均，不可單一年度（2026-10-06 查證原文）

講義**明確要求多年平均**，且附 SQL 範例：

```sql
WHERE date >= DATE('now', '-3 years')
GROUP BY stock_id HAVING AVG(roe) > 0.10
```

講義判斷基準原文：「長年 ROE > 10% 為基本門檻（15%~20% 為優秀，>25% 為超額利潤）」。

**王品反例（講義原文表格）**：ROE 2017~2023 依序為 13.60% / 8.51% / 7.92% / 6.06% / **-4.59%** / 7.53% / **32.90%**。
原文評語：「ROE 長年低檔起伏，唯獨疫情後，受惠民眾外出用餐爆發」。
→ 單看 2023 年那 32.90%（而該年 ROE 位於「>30%」報酬最差區間）會完全誤判。

📌 **此發現與 §4.1 D9 衝突**：D9 記「ROE 用 TTM（近四季）」，理由是「與講義『過去 12 個月的累計 EPS』一致」。
查證後確認**該理由誤植**：「過去 12 個月的累計 EPS」講的是**估值公式的 EPS 輸入**（§4.9 長期價值公式），不是 ROE 篩選條件。
ROE 篩選在講義中是獨立的模組二 指標 1，用的是長年／近 3~5 年平均。**待修正 D9。**

#### ROE × 本益比交叉表（講義原文，資料期間 2002-01-01～2024-12-31）

原文標題：「便宜比績效更重要，但績效優較安心」。未來 5 年年化報酬率：

| 近 5 年平均 ROE | PE 0~5 | PE 5~10 | PE 10~15 | PE 15~20 | PE 20~25 |
|---|---|---|---|---|---|
| < 5% | 4.6% | 8.5% | 9.2% | 8.7% | 7.9% |
| 5%~10% | 4.8% | **13.8%** | 11.6% | 9.2% | 6.9% |
| 10%~15% | 樣本太少 | 12.4% | 9.6% | 7.6% | 4.4% |
| 15%~20% | 樣本太少 | 12.5% | 9.8% | 4.5% | **2.1%** |
| 20%~25% | 樣本太少 | 9.3% | 7.6% | 5.2% | 3.9% |
| 25%~30% | 樣本太少 | 7.2% | 5.0% | 4.3% | **3.0%** |

→ 全表最高 **13.8%** 出現在「ROE 5~10% ＋ PE 5~10 倍」，不是「高 ROE」。
→ **只設 ROE 下限會放行「高 ROE ＋ 高 PE」組合，而那正是報酬最差的格子。**
⚠️ ROE >15% 且 PE 0~5 倍的格子「樣本太少」，不可據以為該區間低PE必然好。

### 4.6 業外獲利比與槓桿為何必須設硬門檻（D4）

五階層杜邦是連乘關係：

```
ROE = 稅賦優勢 × 業外獲利比 × 利益率 × 資產周轉率 × 財務槓桿
其中財務槓桿的講義判準是「不一定」
```

反例：一家公司利益率 3%、資產周轉 1.3、槓桿 4.0 → ROE 15.6%，通過 ROE>12，但獲利能力完全來自借錢。

→ 初篩至少三條件：`ROE > 門檻`、`業外獲利比 ∈ [0.8, 1.2]`、`財務槓桿 < 3`，全部可設定。

> 📌 修正紀錄：本節原寫 `業外獲利比 ∈ [0.8, 1.3]`，該上界是**當初的建議值，非講義原文**。
> 講義程式碼原文為 `ratio >= 0.8 & ratio <= 1.2`（見 `conflict-review.html` 衝突 2 引用的講義片段）。
> 已於 §2.8 定案採用講義值 `[0.8, 1.2]`。

### 4.7 目標本益比：CAGR 不能當獨立上限（推翻 D5 部分）

先前決定「Tier 為主、CAGR 當上限」。查證講義全部 6 個 CAGR→PER 案例後，**「CAGR 當上限」無講義依據**：

| 案例 | 產業 | CAGR | 目標 PER |
|---|---|---|---|
| 1 | 網路通訊設備 | 8% | 12.5~14 |
| 2 | 車用連接器 | **12%** | 16~20 |
| 3 | 豆腐龍頭 | **11%** | **20~25** |
| 4 | 自行車龍頭 | 7.8% | 17~23 |
| 5 | 台積電（2021 初） | 7% | 15~20 |
| 6 | 台積電（2024 初） | **7%** | **19~25** |

三組矛盾證明 CAGR → PER **不是函數**：
- 案例 2 vs 3：CAGR 較高者（12%）拿到較低 PER（16~20）
- 案例 5 vs 6：同一公司、同一 CAGR 7%，目標 PER 4 年間上調近一倍（講者隨時間自行調整定價基準）
- 案例 4：CAGR 僅 7.8% 卻給 17~23 倍

講者用判斷而非公式。豆腐案例的原文評語更寫「11% 複合成長率**似乎過高**」，顯示他把 CAGR 當成需 sanity check 的估計值。

**替代方案（建議，待使用者確認）**：放棄獨立上限，改用講義原有的鏈 — CAGR → 維度 2 分數 → 總分 → Tier → PER。此鏈已是講者原始設計。

> ✅ **已決定（2026-10-06）**：採替代方案，**放棄「CAGR 當獨立上限」**。
> 目標 PER 只由 Tier 決定（§2.9 的對應表），CAGR 僅影響維度 2 分數與長期價值公式的成長假設（§2.16），
> 不再作為 PER 的獨立上限條件。

⚠️ 此鏈**不是硬上限**：維度 2 拿 0 分時，其餘四維各滿分仍可得 80 分（Tier A）。台積電案例 6（CAGR 7% → 19~25 倍）證明講者本就不擋。

### 4.8 主題產業 ≠ 官方產業代碼（影響 industry_research 主鍵）

講義的 17 個產業 CAGR 是**主題產業**，非 TWSE 代碼（01~38）：

```
5G FWA 33%    人工智慧 30%    碳化矽 30%    氮化鎵 26%
電動車   23%    碳捕捉&封存 21%    雲端運算 16%    資安 14%
循環經濟 13%    低軌衛星 13%    數據中心 12%   醫美 12%
設備租賃 11%    智慧製造 10%    綠色能源 9%
```

出處：IDC、TrendForce、Gartner、Statista、MarketsandMarkets、Research and Markets、MarketWatch

講義方法論原文：「無須買報告，只需要開頭的 CAGR 即可，也可以直接問 ChatGPT」

**問題**：一家公司官方分類可能是 `24 電子零組件業`，但主題是「電動車散熱」（如奇鋐）。講義範例表格有 `產業名稱 | 營收比重`，代表要看**該公司營收落在哪個主題**。

→ `industry_research` 主鍵應為 `theme_name` 而非 `industry_code`，且需 `stock ↔ theme` 為多對多。維度 2 應取該公司營收佔比最高主題的 CAGR。

### 4.9 長期價值公式（已驗算，講義內部一致）

```
長期價值 = 近12月累計EPS × (1 + 產業CAGR)^5 × 目標本益比
安全邊際 = (長期價值 − 股價) ÷ 股價
```

驗算案例 1：5.7 × 1.08^5 × 13 = 104.6，講義寫 104~117 ✅

⚠️ 假設「公司 EPS 成長率 = 產業 CAGR」五年不變。粗略，且講義自己會質疑此假設。是否加公司自身趨勢修正，**待使用者決定**。

### 4.10 安全邊際門檻（講義有歧義）

原文：「選價格：長期價值之安全邊際 >100%」、「長期價值 > 80%（或安全邊際 >100%），五年內有翻倍潛力」

⚠️ **兩句話算不過來**：安全邊際 >100% 對應長期價值 > 2× 股價，但「長期價值 > 80%」若指現價 80%，對應安全邊際 −20%，互相矛盾。

⚠️ 講義**所有案例最高只有 93%**，沒有一個達到 100%。此門檻在實務上從未被驗證。

> ✅ **已決定（2026-10-06，§2.7）**：不採講義的 >100%，改為**可設定門檻、預設 50%、不設死硬門檻**，
> 並在介面提示「講義所有實測案例最高僅 93%」。

### 4.11 風險折扣只有概念、沒有公式

原文只說「這一欄的分數，會決定你願意給這家公司多大的安全邊際，以及目標本益比要不要打折」，內文無任何數字或計算式。APP 截圖出現過 `安全折扣_本益比：95折` 單一欄位值。

> ✅ **已解決（2026-10-06，§2.9）**：查證講義原文後確認**風險折扣因子就是五大維度的第 5 項（20 分）**，
> 不是事後的乘數折扣。機制為「扣分 → 總分下降 → Tier 跳級 → PER 整級跳降」。
> 台積電原文：風險折扣僅拿 6 分（理由「致命的地緣政治」），總分 84 → Tier A 25~30 倍；
> 若拿滿 20 分則總分 98 → Tier S 35~40 倍。
> → **不需要自己訂規則**，照講義做即可。但實作要注意這是階梯式而非連續式（見 §2.9）。

**待使用者決定**：先不做，或自行訂規則。

### 4.12 講義數字無法完全重現（實作注意）

用王品 2023 欄驗算五階層杜邦連乘：`0.8 × 0.97 × 7.99% × 1.47 × 3.33 = 30.35%`，講義寫 32.90%，差 8%。
但 2017 欄驗算得 13.64%，講義寫 13.60%，吻合（四捨五入）。

→ 多數年度吻合在四捨五入範圍，2023、2021 明顯對不上，顯示**講義混用不同期間的數字**。

實作時要與講義對帳，但不能期待完全重現；重現不了是講義本身的問題，不是實作 bug。
